# 실제 사고에서 나온 규칙

규칙이 왜 있는지 궁금할 때 읽는다. 각 항목은 "무슨 일이 있었나 → 그래서 무엇을 하나" 순서다. 회차를 돌다 새 사고가 나면 이 형식으로 더한다.

## 테스트가 초록인데 실제로는 죽어 있던 것들

1. **디버그 빌드가 통째로 막혀 있었다.** 리소스 XML 주석 안의 하이픈 두 개 때문이었다. 단위 테스트 수천 건은 리소스를 컴파일하지 않으므로 전부 초록이었다.
   → 측정 전에 실제 빌드를 실제 기기에서 띄운다. "빌드가 된다"는 확인 대상이다.
2. **전 화면 헤더 제목이 흰 배경에 흰 글씨였다.** 테마가 제목 스타일을 주면 헤더의 전경색이 제목에 적용되지 않는 프레임워크 동작이 원인이었다. 위젯 테스트는 "제목 위젯이 있다"만 확인했다.
   → 시각 판정은 스크린샷을 열어서 한다. 디자인 일관성 TC 에 "제목이 배경과 구분돼 읽힌다"를 넣는다.
3. **주소 검색이 어느 기기에서도 뜬 적이 없었다.** 임베드 HTML 의 `onload` 가 뒤쪽 블록에 정의된 함수를 불렀다. 화면에는 "네트워크 연결을 확인해 주세요"만 떴다.
   → 증상 문구로 원인을 단정하지 않는다. 진짜 오류 문자열을 손에 넣는다([drivers.md](drivers.md) §4).
4. **이어 쓴 주문서가 마지막에 제출되지 않았다.** 이어 쓰기가 앞 단계에서 확정한 값을 지웠다. 단계별 테스트는 각 단계만 확인했다.
   → 핵심 여정 TC 는 마지막 단계(서버 기록·목록 반영)까지 한 TC 로 간다. 회귀 테스트는 실물 흐름으로 세운다.
5. **탈퇴는 됐는데 완료 화면이 안 떴다(간헐적으로 로그아웃도).** 세션이 끝나며 화면이 다시 그려져 버튼 위젯이 사라졌고, 이동 코드가 "위젯이 살아 있으면"에 걸려 있었다.
   → 간헐 결함은 타이밍 경합을 의심한다. 테스트는 비동기 완료 시점을 쥐고(Completer) 그 사이에 프레임을 돌려 재현한다.

## 판정이 틀렸던 것들

6. **"화면에 없다" F 5건이 전부 오판이었다.** 스크롤 아래나 다른 탭에 있었다.
   → "없다" F 전에 끝까지 스크롤, 다른 탭·접힌 영역, dump + 스크린샷을 확인한다.
7. **레인 여럿이 "다 됐다"고 보고했는데 심볼·판정이 어긋나 있었다.** 응답이 없는 레인도 나왔다.
   → 레인 보고를 믿지 말고 jsonl 로 센다. 결과가 없는 레인은 결과가 없다는 사실을 적고 그 묶음만 다시 돌린다.
8. **레인이 Major 로 적은 것이 실제로는 핵심 여정 차단이었다.** 안내 문구대로 해도 못 고치고 처음부터 다시 쓰는 것 말고는 길이 없었다.
   → 심각도는 메인이 기준표로 다시 매긴다. 레인은 낮게 적는 경향이 있다.
9. **의도해서 바꾼 동작을 다음 회차 레인이 결함으로 잡았다.**
   → 회차마다 `changes.md` 를 쓰고 지난 회차 내용을 누적한다.
10. **환경 차이를 제품 결함으로 적을 뻔했다.** 공유 DB 가 다른 환경보다 마이그레이션이 뒤처져 있었다.
    → 서버 오류를 결함으로 적기 전에 그 커밋이 기대하는 스키마인지 확인한다.

## 측정 환경이 측정을 망친 것들

11. **API 레인이 UI 레인의 계정을 로그아웃시켰다.** 같은 계정으로 refresh 토큰 재사용을 시험하자, 재사용 감지가 그 계정의 모든 세션을 폐기했다.
    → 계정을 레인별로 나눈다. 세션 파괴 TC 는 전용 계정으로, 다른 레인이 끝난 뒤에 한다.
12. **인증 요청 한도를 레인끼리 나눠 썼다.** 기기와 API 러너가 같은 출발지 IP 로 묶였다.
    → 서버가 믿는 헤더로 출발지를 나누거나, 한도 TC 를 격리 레인으로 뺀다.
13. **측정 도중 서버가 사라졌다.** 에이전트 세션의 백그라운드 셸이 메모리 부족으로 정리됐다.
    → 서버·수신기·기기는 오래 사는 별도 pane 에 띄운다. 레인 수는 메모리가 정한다.
14. **회차 중간에 빌드를 두 번 갈아 끼웠다.** 그 회차의 판정은 어느 코드에 대한 것인지 가를 수 없어 다시 쟀다.
    → 한 회차 = 한 빌드 = 한 커밋.
15. **시드가 조용히 실패했다.** 마스터 코드값이 측정 환경에 없어 FK 위반이 났는데 `INSERT IGNORE` 가 삼켰다. "매핑은 있는데 대상은 0행"인 상태가 만들어졌고, 결함은 한참 뒤 제출 시점에야 드러났다.
    → `INSERT IGNORE` 류로 시드하지 않는다. 시드 검증은 개별 카운트가 아니라 조인으로 한다. 코드값이 그 환경에 있는지 먼저 본다.
16. **키보드 앱이 다시 켜져 붙여넣기 메뉴가 입력칸을 가렸다.** 에뮬레이터를 재기동한 뒤였다.
    → 측정 동안 끄고, 끈 사실과 원복 방법을 드라이버 메모에 적는다.

## 수정 루프에서 배운 것들

17. **위반 주입이 "빨개졌다"고 했는데 실제로는 컴파일 실패였다.**
    → 판정은 종료 코드가 아니라 출력의 실패 블록과 테스트 태그로 한다. 컴파일·로드 실패는 BROKEN 이다.
18. **고정 지연으로 만든 타이밍 테스트가 결함을 재현하지 못했다.** 테스트 프레임워크가 타이머를 프레임보다 먼저 소진했다.
    → Completer 처럼 테스트가 완료 시점을 쥐는 방식으로 쓴다.
19. **외부 리뷰어가 종료 코드 0 으로 끝났는데 판정이 없었다.** 프롬프트만 되풀이하고 끝났다. 2회 연속이었다.
    → 리뷰 결과는 출력 본문의 판정 줄로 확인한다.
20. **되돌린 생성 코드가 다시 쓰이지 않았다.** 코드 생성 도구가 입력이 같다며 캐시를 믿었다. 분석은 초록이고 테스트만 빨갰다.
    → 브랜치·작업 트리를 옮긴 뒤 이상하면 생성물을 지우고 다시 만든다.
21. **작업 트리에서 만든 서버 빌드가 기동하지 않았다.** 커밋되지 않는 로컬 비밀 설정이 그 작업 트리에 없었다.
    → 빌드 전에 로컬 설정을 복사하고, 복사본이 무시 목록에 걸리는지 확인한다.
22. **Workflow 재개가 이미 끝난 레인을 다시 돌렸다.** 캐시는 같은 run 에만 맞는다.
    → 재개 전 journal 의 label 을 대조하고, 아니면 남은 레인만 새 run 으로 돌린다.

## 사람과 일하는 법

23. **회차 중간에 하나씩 묻자 루프가 멈췄다.**
    → 사람 결정이 필요한 항목은 `changes.md` §2 에 "승인 대기"로 적고 계속 잰다. 회차 끝에 한 번에 묻는다.
24. **보고가 결함 ID 와 규칙 번호로 가득해 읽히지 않았다.**
    → "화면에서 무엇이 잘못 보이나"를 쉬운 말로 먼저 쓴다. 숫자는 스크립트에서 가져온다.
25. **시안이 회차 사이에 늘었다**(장수가 두 번 늘었다).
    → 화면 착수와 재측정 직전에 시안을 다시 읽고 장수를 대조한다.
