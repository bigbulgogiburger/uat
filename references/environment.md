## 1. 프로필 (`uat.config.json`)

프로젝트당 하나다. `assets/uat.config.example.json` 을 복사해 채운다. 코드와 설정에서 알 수 있는 값은 사용자에게 묻지 않는다.

| 키 | 뜻 | 쓰는 스크립트 |
|---|---|---|
| `project` · `repo` | 이름 · 저장소 경로 | 보고서 · Workflow args |
| `runs_dir` | 회차 폴더의 부모. 저장소 밖(세션이 끝나도 남는 곳) | init_run |
| `lane_guide` | 프로젝트용으로 채운 레인 가이드 경로 | plan_lanes args |
| `secrets_file` | 별칭별 비밀 값 JSON(저장소 밖 · 본인만 읽기) | api · secret_type · 비밀 검사 |
| `data_prefix` | UAT 가 만드는 데이터의 접두어 | 가이드 · db write_guard |
| `areas` | 영역 문자 → 이름. 순서가 문서 순서 | tc_merge · render_* |
| `methods` | 허용 method 목록 | tc_merge |
| `drivers.ui` | `android` 또는 `web` | measure.js 프롬프트 |
| `android.*` | adb 경로 · 패키지 · 시리얼 · clip dex 위치 | android/ui.py |
| `api.*` | base_url · 기본 헤더 · 인증 헤더 · 로그인/갱신 시퀀스 · 토큰 TTL | api.py |
| `db.*` | 읽기/쓰기 명령 배열(`{sql}` 자리) · write_guard | db.py |
| `redact_patterns` | 비밀처럼 보이는 문자열 정규식(출력 가림 · 기록 거부) | 전부 |
| `lanes.*` | 분할 규칙 · 모델 · 추론 강도 | plan_lanes |
| `carry_work` | 다음 회차로 넘길 `work/` 파일 | init_run |

`_` 로 시작하는 키는 설명용이고 스크립트가 무시한다.

## 2. 외부 발송 차단 — `sink.py`

UAT 중 실제 고객·직원에게 SMS·알림톡·메일이 나가면 그 자체가 사고다. 발송 경로를 전부 찾아 로컬 수신기로 돌린다.

1. **발송 경로 목록을 만든다.** 서버 설정에서 외부 호스트(SMS·알림톡·메일·푸시·결제·세금계산서·웹훅)를 grep 한다. 직접 띄우는 서버뿐 아니라 **위임 대상 서버**(다른 팀 서버가 대신 보내는 경우)까지 본다.
2. **로컬로 돌린다.** 각 서버의 발송 base URL·SMTP 호스트를 `127.0.0.1:<포트>` 로 바꾼 로컬 전용 설정으로 띄운다. 설정 파일을 커밋하지 않는다. 실행 인자나 로컬 전용 프로필로 준다.
3. **수신기를 띄운다.**
   ```bash
   python $S/sink.py --http 18080 --smtp 2525 --rules RUN/work/sink-rules.json --log RUN/work/sink.log
   ```
   `rules.json` 은 경로 정규식 → 응답(상태코드·바디)이다. 발송 API 가 "성공" 응답을 받아야 다음 단계로 가는 앱이면 성공 바디를 흉내 낸다. 로그에는 시각·메서드·경로·크기만 남는다. 본문(번호·문구)은 남기지 않는다.
4. **푸시**는 서버의 푸시 SDK 를 초기화하지 않는 방법이 가장 확실하다(자격 증명 미주입). 앱이 저장만 하고 보내지 않는 폴백이 있는지 확인한다.
5. **검증**: 측정 전에 발송이 일어나는 TC 하나를 메인이 직접 밟고, 수신기 로그에 한 줄이 생기는지, 외부로 나간 흔적(서버 로그의 외부 호스트)이 없는지 본다.
6. 차단할 수 없는 발송(실결제 등)은 레인 가이드 절대 규칙에 "누르지 않는다"로 넣고, 그 TC 는 BLOCKED 로 설계한다.

인증번호 SMS 는 보통 **심사·테스트용 고정 번호 화이트리스트**가 있다. 화이트리스트 밖 번호로 인증을 요청하지 않는다. 테스트 계정이 화이트리스트에 있는지 측정 전에 확인한다.

## 3. 계정 분할

| 계정 | 쓰는 곳 | 이유 |
|---|---|---|
| 계정#1 | UI 레인 기본 | 이력이 쌓인 일반 회원 |
| 계정#2 | API 레인 전용 | 토큰 재사용 감지·강제 만료 TC 가 UI 세션을 끊지 않게 |
| 계정#3 | 빈 계정 · 탈퇴 TC | 이력 0 화면 · 되돌릴 수 없는 전이 |
| 비회원 | 비회원 경로 | 로그아웃 상태 |

- 한 계정의 세션을 두 레인이 동시에 쓰지 않는다. refresh 토큰 회전·재사용 감지가 있으면 한쪽이 다른 쪽을 로그아웃시킨다. 그러면 레인은 그것을 "갑자기 로그인 화면으로 튕김" 결함으로 잡는다.
- **IP 축 한도**(인증 요청 횟수 등)는 기기와 API 러너가 같은 출발지로 묶인다. 서버가 `X-Forwarded-For` 를 믿는 구조면 API 러너에 문서용 IP(203.0.113.x)를 기본 헤더로 주고, 한도를 재는 TC 는 TC 전용 IP 를 쓴다. 믿지 않는 구조면 한도 TC 를 `isolated` 로 빼서 맨 끝에 돈다.
- 탈퇴 TC 는 탈퇴해도 되는 계정으로만 한다. 탈퇴 뒤 같은 번호로 재가입이 막히는 정책이면 측정 전에 정리 방법을 정한다.

## 4. 비밀 다루기

- 비밀 파일(`secrets_file`)은 저장소 밖에 두고, 본인만 읽게 권한을 건다. 모양은 `assets/examples/secrets.example.json`.
- 에이전트는 비밀 파일과 토큰 캐시(`work/.tok-*.json`)를 열지 않는다. 화면 입력은 `android/secret_type.py <별칭> <KEY>`, API 는 `api.py` 의 `{{별칭.KEY}}` 를 쓴다. 두 도구 모두 값을 출력하지 않는다.
- `verdict.py` · `defects.py` · `tc_merge.py` 는 `redact_patterns` 에 걸리는 문자열이 든 기록을 **거부**한다. 거부되면 값을 별칭으로 바꾼다. 패턴은 프로젝트에 맞게 더한다(주민번호·카드번호·이메일 등).
- DB 접속 정보는 `db.*` 명령이 가리키는 파일(예: `--defaults-extra-file`)에만 둔다. 명령 배열에 비밀번호를 직접 쓰지 않는다.
- 운영 환경의 키·암호화 키는 dev 와 다를 수 있다. 측정 환경의 키를 운영 설정과 비교하는 일은 UAT 범위가 아니다. 다만 다르다는 사실을 발견하면 배포 게이트 목록에 남긴다(값은 쓰지 않는다).

## 5. 데이터 — 접두어 · 상태 시드 · 원복

- 앱으로 만드는 데이터에는 `data_prefix` 를 붙인다(이름·제목·내용). 공유 DB 에서 UAT 데이터와 실제 데이터를 가르는 유일한 표시다.
- 만든 데이터는 `work/requests.jsonl` 에 한 줄씩 남긴다(번호·계정 별칭·레인·목적). 다른 레인이 재사용하고, 정리 때 목록이 된다.
- **앱이 만들 수 없는 상태**(배정·배송 중·완료·지연 등)는 프로젝트 전용 **상태 시드 도구 하나**로만 만든다. 그 도구는 다음을 지킨다.
  - 대상을 이번 회차에 UAT 가 만든 데이터로 제한한다(접두어·계정으로 검사)
  - 바꾸기 전 값을 `work/state-snapshots.json` 에 스냅샷하고 `revert` 로 되돌린다
  - 상태 전이를 서버 코드의 실제 전이 규칙대로 만든다(작성 레인이 TC 의 `data_setup` 에 적은 테이블·컬럼·값이 명세다)
- 직접 SQL 쓰기는 `db.py w` 로만 한다. 이유(`--why`)와 원복 SQL(`--revert`)이 필수다. `write_guard`(접두어)가 없는 SQL 은 거부된다. DDL·WHERE 없는 UPDATE/DELETE 는 언제나 거부된다.
- `INSERT IGNORE` 류로 시드하지 않는다. FK 위반까지 삼켜서 "행은 있는데 참조 대상은 없는" 상태를 만들고, 그 결함은 한참 뒤 엉뚱한 화면에서 터진다. 시드 검증은 개별 카운트가 아니라 **조인**으로 한다.
- 마스터 코드값을 시드에 박을 때는 그 코드가 측정 환경에 있는지 확인한다. 어떤 환경에만 있는 코드가 있다.

## 6. 메모리 · 오래 사는 pane

| 항목 | 대략의 메모리 |
|---|---|
| Android 에뮬레이터 | 2~4GB |
| 브라우저 | 2~3GB |
| 서버 1개(JVM 등) | 0.5~1.5GB |
| 에이전트 터미널(pane) 1개 | 0.5~0.7GB |
| 빌드 데몬(Gradle 등) | 1~2GB |

- **서버·수신기·에뮬레이터는 오래 사는 별도 터미널(pane)에 띄운다.** 에이전트 세션의 백그라운드 셸은 메모리가 모자라면 정리된다. 그러면 측정 도중 서버가 사라지고, 레인은 그것을 "연결 실패" 결함으로 적는다.
- 측정 중 여유 < 1.5GB 면 새 레인·pane 을 띄우지 않는다. `memguard.py --min 1.5` 로 본다.
- 메모리를 확보할 때는 사용자가 허용한 유휴 프로세스(유휴 빌드 데몬, 끝난 테스트 러너)만 정리한다. 보안 에이전트·사용자 프로그램·측정 중인 서버는 건드리지 않는다. 자기 세션이 띄운 것만 닫는다.
- 메모리 부족으로 강제 종료된 백그라운드 작업을 사용자 요청 없이 다시 띄우지 않는다. 무엇이 왜 죽었는지 보고한다.

## 7. 빌드 · 서버 · 스키마

- **한 회차 = 한 빌드.** 서버와 클라이언트를 같은 커밋으로 빌드하고, 회차 중간에 바꾸지 않는다. 회차 중간에 수정본으로 갈아 끼우면 어느 판정이 어느 코드에 대한 것인지 알 수 없게 된다. 실제로 가이드에 "빌드 교체" 절이 두 번 붙은 회차가 있었는데, 그 회차의 판정은 다음 회차에 다시 재야 했다.
- 빌드는 메인이 측정 전에 직렬로 한 번 한다. 레인은 빌드하지 않는다.
- 작업 트리를 따로 쓰면(git worktree 등) 커밋되지 않는 로컬 설정 파일(비밀 프로필)이 없다. 빌드 전에 복사하고, 복사본이 무시 목록에 걸리는지 확인한다.
- 코드 생성 도구는 입력이 그대로면 캐시를 믿고 되돌린 생성물을 다시 쓰지 않을 수 있다. 브랜치를 옮긴 뒤 빌드가 이상하면 생성물을 지우고 다시 만든다.
- **스키마**: 측정 DB 가 그 커밋이 기대하는 마이그레이션까지 와 있는지 확인한다. 공유 DB 는 다른 환경보다 뒤처져 있을 수 있다. 서버 오류를 결함으로 적기 전에 마이그레이션 목록과 실제 스키마(information_schema)를 대조한다.
- 디버그 빌드가 실제로 기동되는지 기기에서 확인한다. 리소스 파일 한 줄 때문에 디버그 빌드 전체가 막혀 있던 적이 있다. 단위 테스트는 그것을 잡지 못한다.

## 8. 측정 전 점검표

- [ ] 서버·앱 빌드 커밋 sha 가 같다(`run.json` 에 기록)
- [ ] 스키마가 그 커밋 기대치다
- [ ] 수신기가 떠 있고, 발송 TC 1건으로 로그 한 줄을 확인했다
- [ ] 서버·수신기·기기가 오래 사는 pane 에 있다
- [ ] 계정 별칭별 로그인이 된다(`api.py login <별칭>` · 화면 로그인 1회)
- [ ] 상태 시드 도구가 이번 회차 폴더를 가리킨다
- [ ] 기기 설정(키보드·글자 크기·회전·네트워크)이 기본값이고, 바꾼 것은 `driver-notes.md` 에 원복 방법과 함께 적었다
- [ ] 여유 메모리 ≥ 레인 수에 맞는 값
